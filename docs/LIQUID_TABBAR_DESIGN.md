# 红果实验性液态玻璃底栏设计

状态：设计稿，尚未实现或发布。依据红果 7.3.9 / 7.3.9.32、FLEX 1792333416 及此前合集快照。

## 目标与术语

- 底栏使用系统 UIGlassEffect，保留首页、剧场、我的三个原生入口。
- 底栏区域没有实时视频画面时，以纯黑背景承托玻璃胶囊。玻璃本身可能显示深灰高光，不承诺胶囊像素纯黑。
- 实验性“竖屏视频铺满屏幕”允许符合条件的当前视频等比放大，使实时画面延伸到玻璃底栏下方。
- 这里的“铺满屏幕”是竖屏画面扩展，与调用红果原生按钮进入横屏播放是两项功能。
- 竖屏视频不显示插件的“全屏观看”入口；横向视频继续沿用固定锚点与原生横屏事件。

## 已知布局

| 对象 | 当前快照 | 设计约束 |
| --- | --- | --- |
| 窗口 | 402×874 | 使用实际窗口和安全区，不能固定设备尺寸 |
| FQVCollectionView / 当前视频单元 | 402×784 | 分页步长、offset、contentSize 保持原生 |
| TTPlayerView | 402×784 | 这是渲染容器，不能直接等同于视频文件分辨率 |
| 观看完整短剧 | y740，高44 | 保持文案、点击和原生位置 |
| CYLTabBar、SSTabBar | 均 y790，高84 | 有两套底栏，需要共同梳理背景层 |
| SSTabBar 背景 | 三层效果视图、一张背景图 | 单纯增加第四层效果不能解决灰底叠加 |
| 三个文字按钮 | 宽131.3，高49.7 | 保留原按钮及事件，不再次修改它们的 frame |

## 参考 DYKiller 的结论

参考仓库 subezhj/DYKiller，读取时 main 提交为 3d7a3ae6cdf72d60b0c0ac3e9374549d2dcb86eb。

- DKGlassTabBar.xm：使用 UIGlassEffect，区分 Regular / Clear；同步宿主显隐、选中状态，恢复自己接管的背景；重复布局先比较再写入。
- DKVideoGeometry.xm：视频全屏独立于玻璃模块，按视频模型比例筛选，不把横向视频一律裁切铺满。
- DKVideoPageChrome.xm：背景有独立策略，包含深色及封面主色路径。红果本设计采用用户指定的黑色回退，不复制其主色策略。
- DYKiller 的抖音控制器、列表及几何拦截规则不能直接应用到红果。原生系统 TabBar 的拖动交互也不会仅靠添加玻璃材质自动获得。

## 视觉与交互

保留 SSTabBar 84 pt 原生占位。玻璃胶囊放在原生文字行区域内，左右内缩约12 pt，视觉高度约50 pt；最终按实际文字行和安全区计算。先不开放高度、位置滑条。

从后到前：黑色回退背景 / 已验证覆盖的实时视频 → 单一玻璃胶囊 → 原生文字、徽标与按钮。

首次接管保存 CYLTabBar 和 SSTabBar 对应背景、效果视图、图片及分割线的宿主状态；只处理确认属于底栏的装饰层。关闭后恢复，不删除宿主对象，不隐藏整个 TabBar 来实现背景清理。

玻璃背景不接收触摸；原生 SSTabBarTextButton 负责点击。首版不替换为第二套可交互 UITabBar，不复制导航栈，也不修改原按钮的 frame、transform、target/action。保持选中状态和文字缩放同步。

UIGlassEffect 可用时才启用液态玻璃模式。不可用时显示明确状态，回退黑色原生底栏，不把普通模糊标成液态玻璃。首版使用深色 Regular，Clear 留到真机验证后单独考虑。

## 视频覆盖判定与黑色回退

“有视频”要求当前可见视频的实时渲染画面能够覆盖底栏区域，不是只要视图树里存在 FQVPlayer 就算。

| 页面/状态 | 底部背景 | 视频行为 |
| --- | --- | --- |
| 当前画面已经自然覆盖底栏 | 实时视频 | 不额外放大 |
| 竖屏视频可验证扩展，实验开关开启 | 扩展后实时视频 | 等比放大，允许裁切左右边缘 |
| 实验开关关闭 / 横向视频 / 比例未知 / 无可用渲染路径 | 黑色 | 保持原生画面 |
| 剧场、我的、加载失败、广告或非视频内容 | 黑色 | 不扩展 |
| 合集独立播放页无首页底栏 | 不挂首页胶囊 | 仅处理该页横屏入口显隐 |
| 原生横屏、画中画、其他窗口 | 不应用该实验布局 | 跟随宿主显示 |

滚动切换或渲染器尚未稳定时先黑底，不沿用上一条视频画面，不用截图伪造实时视频。黑底只放在原生底栏区域内，不向上覆盖标题或视频。

## 实验性竖屏视频铺满

先记录运行时当前视频尺寸、渲染器、父级裁切链、坐标和原生内容模式，确认操作对象属于当前视频，排除预加载单元。尺寸未知时不尝试；高竖屏比例才进入实验，初始候选阈值高/宽≥1.70，最终由真机样本校准。

使用等比 aspect-fill，目标覆盖当前屏幕的视频背景区域，不拉伸宽高比，不强行放大横向视频。402×784 到 402×874 的容器覆盖示例，放大因子约1.115，横向会裁切约23 pt/侧；实际裁切还取决于原始视频比例与内容模式。

实现调研优先寻找播放器已有的内容模式/显示范围能力。若只能实验性修改渲染表现，则仅接管当前视频的渲染层及必要裁切边界，保留原生控制层。任何修改都要独立记录、比较后写入、可恢复，不在 layoutSubviews 内反复扩展父级几何。

关键限制：当前 collection 截止 y784，只放大 TTPlayerView 不能保证画面穿过父级裁切抵达 y874。需要验证裁切链；不得直接对整个列表关闭裁切，否则可能泄露相邻单元。没有证明当前单元可独立裁切与恢复前，保持黑底，不能宣称视频已铺满。

不复用 experimental/HGFullTabAllocation.m；不改 collection bounds、cell 高度、分页属性、contentSize 或 contentOffset；不移动标题、右侧控件、全集入口。扩大画面与文字缩放分别管理。

## 设置结构

底栏设置：

- 液态玻璃底栏（实验）：默认关闭。
- 竖屏视频铺满屏幕（实验）：默认关闭；依赖玻璃开关，独立控制视频扩展。
- 适配状态：系统材质是否可用、当前视频比例、实时覆盖/黑底回退及原因。

实验模式与旧“深色模糊背景 / 实际高度调整”互斥。启用实验时只暂停旧路径，保留旧设置值；关闭实验恢复旧路径。避免增加重复设置。黑底回退是固定行为，不再新增开关。

诊断只记录，不以布局次数自动暂停功能，不恢复用户此前要求屏蔽的布局保护。

## 实现次序与验收

1. 先实现竖屏隐藏横屏入口，以及玻璃胶囊、黑底、原生点击、关闭恢复。此阶段即使播放器完全不能扩展也可使用。
2. 在运行时诊断确认视频比例、渲染器和裁切路径后，实现独立的视频扩展实验。路径不可用时给出原因并黑底回退。
3. 模拟器验证重复布局幂等、背景不叠加、选中/点击/字体、配置互斥及恢复；专门检查宿主拒绝几何更改时不形成布局循环。
4. 真机验证冷启动、连续刷视频、首页/剧场/我的切换、进入合集再退出、弹出评论/分享、横竖视频交替、开启关闭与恢复。视频扩展必须验证无相邻视频泄露、无分页错位、无冻结。

通过玻璃与黑底验收后再发首个实验构建；视频铺满只有在真机验证后才标注对应页面支持，不把布局单元测试作为真机可用证明。
