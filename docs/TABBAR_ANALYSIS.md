## 修复策略

1. 保留原 SSTabBarTextButton 及点击回调。在它的 setFrame 写入处按胶囊的真实宽高等分，避免宿主晚于父布局写回旧坐标。
2. 在按钮布局后居中实际文字容器，而不是只修改父按钮的位置。
3. 隐藏独立旧磨砂层、整条背景图片和分割线，恢复关闭状态时的原始显示状态。保留文字行、按钮和徽标。
4. 原底栏宿主区域由扩展的视频列表覆盖；底部分发信息保持入口动作，去除与悬浮底栏连接的实心背景。
5. 高度使用44–80pt范围，默认54pt。上下居中、圆角、底部安全区间距与HUD锚点共用该高度。
6. 不再在每次控制器布局后无条件再次 setNeedsLayout 底栏，也不全树标记加同步 layoutIfNeeded。

## 右侧卡死分析

首版在每次右侧布局前恢复 transform/frame，布局后又改变 transform、center 和容器高度。两个阶段即便设置值不变也会产生几何写入，存在持续触发布局和阻塞主线程的风险。
没有真机线程采样或崩溃堆栈，因此这是代码层定位到的风险，不是已经取得的真机调用栈结论。

0.1.1 对原点击视图的子图层做视觉缩放，保持点击视图的 transform 和 bounds。只在矩阵或目标坐标变化时写入，且不在下一轮布局前恢复。隐藏控件的重排在宿主 frame 写入处保持一致。

模拟器夹具故意不断写入旧按钮坐标和背景尺寸，连续切换55%、80%、100%缩放，以及44、80、54pt底栏高度，检查坐标、恢复、点击动作和布局是否收敛。真实红果与红果净化共同注入仍需设备验收。
## 0.1.3：真机保护记录与新的修复路径

用户后续截图记录SSTabBarTextButton layoutSubviews在250ms内超过120次，并已暂停增强。这证明循环保护捕捉到了该按钮布局路径；不等于已经获得完整线程采样。

旧方案在按钮layoutSubviews后改写按钮和文字容器frame。宿主有可能通过约束或后续布局再次恢复原几何，形成反复校正。新方案删除这些几何写入，也不再改变文字行的宽高。

按钮的子图层平移由宿主实时文字中心与悬浮栏等分中心计算，不缓存固定的32pt文字宽度。不变更字体纵横比，也不改变原控件的UIView.transform。

原按钮仍负责事件处理。SSTabBar的hitTest根据胶囊槽位返回原按钮，原按钮pointInside使用同一槽位判断跟踪触点，包含视觉区域边缘与较高底栏区域。

新回归夹具会在检测到按钮或文字容器几何被修改时继续请求布局，模拟宿主拒绝几何改写的情形。验证原几何保持不变、文字视觉中心、左右边缘命中、原点击动作、多个高度、关闭恢复、历史状态、保护后重试及滑条卡片内边距。
